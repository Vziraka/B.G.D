# Speech recognition comparison prepared on 22 September 2026

The smallest useful comparison is **the corrected existing Vosk recognizer against whisper.cpp tiny.en**, on the same short local synthetic WAV files. Do not replace production Vosk merely because Whisper is newer or uses a different architecture. No recognition benchmark, asset download, user microphone capture or Pi command was run for this research while the separate 600-second performance measurement was active.

## Existing implementation and concrete correction

`speech_prototype.py` normalizes browser audio with FFmpeg to 16 kHz mono signed16 PCM, caps recordings at 30 seconds, loads the isolated Vosk model once, and deletes temporary input/normalized files. The server serializes recognizer access. Its configured runtime is Vosk0.3.45 with `vosk-model-small-en-us-0.15`; no vocabulary restriction is passed to `KaldiRecognizer`, so phrase hardcoding is in interpretation rather than an intentionally closed recognition grammar. The model catalog identifies this40MB model for Raspberry Pi and lists Apache2.0 licensing; its corpus WER figures are not this project's accuracy. [Official model catalog](https://alphacephei.com/vosk/models)

Inspection found that the wrapper ignored finalized segments from `AcceptWaveform()` and returned only `FinalResult()`. Internal pauses could therefore discard earlier parts of a natural request. The official file-transcription example retrieves `Result()` when `AcceptWaveform()` reports an endpoint, then retrieves `FinalResult()` at end of file. The wrapper now concatenates those finalized segments in order and skips blanks. Four local fake-recognizer tests cover earlier clauses/negation, blank segments, continuous speech and empty rejection; they also check deletion of temporary WAVs. This is an API-plumbing correction, not measured acoustic accuracy. [Vosk example](https://raw.githubusercontent.com/alphacep/vosk-api/master/python/example/test_simple.py), [pinned0.3.45 recognizer implementation](https://raw.githubusercontent.com/alphacep/vosk-api/v0.3.45/src/recognizer.cc)

The browser now stops automatically at29.5seconds, leaving encoding/scheduling headroom below the unchanged server30-second limit. It remains push-to-talk; no background microphone capture is added.

## Predeclared bounded evaluation

Use `speech-comparison-corpus-2026-09-22.json`: ten speech clips plus silence and seeded noise. Generate speech locally with one already-installed Windows voice after the performance run, normalize once, and retain clip hashes and exact synthesis settings. One case has explicit two-second pauses to exercise finalized segments. No owner recording or private audio is required. Do not fetch a public dataset for this first comparison; synthesized commands directly test the requested domain and avoid unclear recording rights.

Run the corrected production Vosk wrapper on the Pi, then the isolated tiny.en CLI on the exact same WAVs, one request at a time. Use a fixed low thread count and the CPU scheduling allocation agreed with the performance owner. Initial CLI settings: English, CPU-only, one thread, default full audio context, no vocabulary prompt, temperature0, no temperature fallback, JSON output. The pinned CLI supports these flags: `-l en -ng -t 1 -tp 0 -nf -oj`; verify executable help before use. Avoid Raspberry-Pi examples' reduced audio context until a controlled later comparison because changing it could change recognition. [Pinned CLI parameter source](https://raw.githubusercontent.com/ggml-org/whisper.cpp/v1.9.4/examples/cli/cli.cpp)

For each clip retain reference text, actual transcript, normalized word error rate, critical-word/negation retention and whether silence/noise produced text. Compute latency from audio submission to final transcript, alongside clip duration, peak process RSS and camera/vision/display FPS, frame delay, power flags and temperature. Report Vosk cold model load separately from its cached calls. CLI subprocess results include model loading; label them accordingly rather than presenting them as warm decoder latency. Set a60-second per-clip process timeout and stop a candidate promptly if it causes sustained camera degradation; no transcript goes to a mission endpoint.

Do not select a replacement unless it preserves every Stop and negation test, improves actual transcription errors, rejects non-speech and retains the existing combined-workload criteria. These twelve synthetic cases can reject a bad candidate or justify further testing; they cannot qualify recognition of the owner's real voice, microphones, distance, wind, motor noise or arbitrary conversational speech. If tiny is useful but startup dominates, only then evaluate a persistent local process. Keep raw user audio temporary and offline if later physical testing is authorized.
