# MicoAir743 original: USB-only identity and baseline (revision 1, 28 September 2026)

**Scope:** a disconnected, loose flight controller on the Windows bench. This card releases a **read-only** first connection and backup of existing settings. It does not release firmware flashing, parameter writes, receiver binding, calibration, motor tests, aircraft battery power, or flight. The complete controller stage remains runbook C4, **NOT RELEASED**. Do one numbered action at a time; check its result before continuing. An owner report that the Pyrodrone parcel arrived is not a physical board-variant or firmware check.

The selected item is Pyrodrone's MicoAir 743 / 50A Bluejay stack, SKU `U4-13756`. The selected flight controller is the **original MicoAir743** (separate 30.5 mm mounting pattern), for which the manufacturer's manual lists a USB Type-C connector. ArduPilot publishes a distinct `MicoAir743` firmware target; `MicoAir743-Lite`, `MicoAir743v2`, and `MicoAir743-AIO` are different targets. The current `stable/MicoAir743` firmware manifest returned ArduCopter `4.7.1` on 28 September 2026. None of that establishes what firmware is already on the delivered board. [Pyrodrone stack](https://pyrodrone.com/products/micoair-743-stack-with-h743-bmi088-flight-controller-and-2-6s-50a-bluejay-4in1-esc-30x30mm); [MicoAir original manual](https://micoair.com/docs/micoair743-user-manual/); [ArduPilot original-board page](https://ardupilot.org/copter/docs/common-MicoAir743.html); [ArduPilot stable target](https://firmware.ardupilot.org/Copter/stable/MicoAir743/).

## 0. Identify the loose board before connecting it

**Power:** flight battery disconnected and set away from the bench; propellers removed. Leave the flight controller separate from the speed controller and every other peripheral. Do not attach the included 8-pin stack cable or any sensor plug for this check. If the two boards arrived already assembled or cabled together, do not pull them apart just for this card; report that condition so the connection method can be checked first. Do not touch the board with the iron.

Place the flight controller on a clean, dry, nonconductive surface. Compare its printed model name, connector layout and included product label with the [original MicoAir743 manual](https://micoair.com/docs/micoair743-user-manual/) and the ordered [Pyrodrone stack](https://pyrodrone.com/products/micoair-743-stack-with-h743-bmi088-flight-controller-and-2-6s-50a-bluejay-4in1-esc-30x30mm). Locate the board's USB connector without forcing a cable into it. Record the exact board text and any revision marking in words. A photo is useful only if the marking cannot be read or the layout conflicts with the manual. If the board says Lite, v2, AIO, or the marking/layout differs, stop here for a revised card.

**Pass:** board marking and layout identify the original MicoAir743, with no visible shipping damage or loose metal touching it. **Report:** exact model/revision text, or the mismatch. Do not infer the firmware from the packaging.

## 2. Connect and read, without flashing

With the loose board still isolated, connect its USB port to the PC. Wait several seconds for the board to finish starting. In Windows Device Manager, inspect **Ports (COM & LPT)** for the new device and note its exact name and `COM` number. If the board already runs ArduPilot, the manufacturer's [first-install guide](https://micoair.com/docs/loading-firmware-micoair743/) says it should enumerate as an ArduPilot COM device. In Mission Planner choose that new COM port, set `115200`, and click **CONNECT**. Wait for Mission Planner to finish downloading parameters. [ArduPilot connection instructions](https://ardupilot.org/planner/docs/common-connect-mission-planner-autopilot.html).

**Pass:** Mission Planner's button changes to **DISCONNECT** and a parameter download completes. In its **Flight Data → Messages** view, write down the displayed vehicle/firmware version. The loose-board attitude display may respond to a gentle hand tilt, but no movement test is needed to pass this stage. A zero or missing battery/GPS/radio reading is expected while those items are disconnected; it is not permission to bypass an arming check.

**If it does not connect:** stop the USB attempt and report the board marking, the exact Windows device name/COM number (or that no new device appeared), and Mission Planner's exact error. One retry with the same cable after unplugging and waiting a few seconds is reasonable because ArduPilot documents a bootloader-startup timing issue. Do not press a BOOT button, enter DFU, erase, flash, reset parameters, or connect the flight battery as a connection workaround. A board with other firmware or no bootloader needs a separately checked original-board installation procedure. [MicoAir firmware guide](https://micoair.com/docs/loading-firmware-micoair743/); [ArduPilot firmware-loading distinction](https://ardupilot.org/planner/docs/common-loading-firmware.html).

## 3. Save the untouched parameter baseline

Only after the connection in step 2 succeeds, open **CONFIG → Full Parameter Tree** in Mission Planner and click **Save to File**. Save a `.param` file named `MicoAir743-before-changes-2026-09-28.param` in a known location on this PC. The file is a backup of the settings *actually read from this board*, not a configuration to upload. Record the full file path and the firmware/version text from Messages. [Mission Planner parameter-screen guide](https://ardupilot.org/planner/docs/mission-planner-configuration-and-tuning.html); [ArduPilot backup-before-upgrade guidance](https://ardupilot.org/planner/docs/common-loading-firmware.html).

**Pass:** the `.param` file exists and is nonempty. Click **DISCONNECT**, then unplug USB. **Report:** saved file path, firmware/version text, and any startup error messages. There is no need to manually transcribe every parameter or send a routine photo; the project agent can inspect the file on the shared PC. If the save fails, leave the controller's settings untouched and report the error.

## Engineering follow-up: configuration is a separate release

The agent compares the physical variant and saved baseline with the selected `MicoAir743` target and runbook C1/C4 wiring. Useful baseline fields include `FRAME_CLASS`, `FRAME_TYPE`, `MOT_PWM_TYPE`, `SERIAL1_PROTOCOL`, `SERIAL3_PROTOCOL`, `SERIAL4_PROTOCOL`, `SERIAL5_PROTOCOL`, `BATT_MONITOR`, `BATT_VOLT_PIN`, `BATT_CURR_PIN`, and `ARMING_CHECK`. These are **inspection fields, not instructions to set values**. Some ports and battery readings are absent on USB alone. Receiver, GPS, flow sensor, ESC and whole-battery monitor setup require the checked wiring, mounted orientation and staged power tests. Do not copy a saved parameter file onto a different firmware version or select a similar-sounding firmware target. ArduPilot warns against restoring old parameter files to newer firmware and documents separate procedures for a board that lacks its ArduPilot bootloader. [ArduPilot firmware guide](https://ardupilot.org/planner/docs/common-loading-firmware.html).

**Gate to later C4:** exact physical original-board identity, current firmware/vehicle type, saved untouched baseline, released wiring drawing, powered-supply checks and mounted orientation. Future controller card must supply an explicit parameter change list, backup/rollback method, calibration order, receiver/sensor and failsafe checks, and props-off motor test. Leave all pre-arm safety checks enabled while waiting for that release.
