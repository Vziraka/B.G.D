# Improving the current local language model — 27 September 2026

**Decision:** keep Qwen3.5-4B Q4_K_M as an experimental candidate, disabled by default. Its weights have **not** been fine-tuned. The newly sealed PC text trial failed 45/50 consequential and 43/50 ordinary cases. Later open-development prompt and interpreter changes improved familiar requests but still failed independent consequential probes. Rev12 passed the original 30 and development-v2 58 exactly, but scored 17/18 consequential and 10/20 ordinary on a separate new root probe. A controlled Q6_K copy of the same weights corrected two ordinary location questions but introduced two consequential errors and a 30-second cold timeout, so Q6 is rejected. The current priority is a general request-boundary/target repair and a controlled prompt comparison, followed by new open evidence and a different unseen sealed trial. No PC text score authorizes Pi or speech use.

## What has and has not been tried

The pinned Qwen3.5-4B GGUF is 3.013 GB and ran with non-thinking settings `temperature=0.7`, `top_p=0.8`, `top_k=20`, `min_p=0`, `presence_penalty=1.5`, matching the [Qwen model card's non-thinking recommendation](https://huggingface.co/Qwen/Qwen3.5-4B). Its prompt and guarded application code went through seven development revisions. Rev7 passed the open sets but scored 88/100 on the newly sealed set; [the one-run review](../../tmp/language-candidate-20260927/sealed-v3/review.md) separates policy/target bugs from model misunderstandings. Older Qwen3-4B, SmolLM3-3B and Phi-4-mini profiles were tested and rejected; see [the acceptance record](pi-conversation-acceptance-2026-09-26.md). No LoRA, QLoRA or full-weight training has been run on this project.

The model itself misunderstood clear novel follow, find and count paraphrases in three ordinary sealed cases. It also proposed an unavailable scout action for an out-of-view request, which the strict validator rejected. Seven other misses came from surrounding clause/target logic rather than model inference. Rev12 open evidence exposed the same split: some clear location/status questions drew false clarification or refusal from the model, while the source path accepted a target known only to the speaker. Training weights before the deterministic defects are corrected would blur the source of improvement and would not repair an unsafe validator or stale timeout.

## Available paths and gates

| Path | What it could improve | Evidence needed before adoption |
| --- | --- | --- |
| Better task instruction and boundary reconciliation | Novel phrasing without changing a 3 GB artifact | New open paraphrases with positive/negative neighbors, no consequential regressions, then a new sealed set. The current sampling already follows Qwen's documented non-thinking profile, so changing temperature alone has no sound basis. [Qwen model card](https://huggingface.co/Qwen/Qwen3.5-4B) |
| A less aggressive quantization of the same weights | Possible recovery of decisions lost in four-bit conversion | The pinned [Q6 development comparison](../../tmp/language-candidate-20260927/quant-comparison/review.md) failed the no-consequential-regression gate (17/19 versus Q4's 19/19) and timed out cold at 30 seconds. Do not promote this Q6 artifact. [llama.cpp's quantization tools](https://github.com/ggml-org/llama.cpp/blob/master/tools/quantize/quantize.cpp) describe the formats; their example perplexity numbers are for other models and do not predict this project's command accuracy. |
| LoRA/QLoRA adapter on the current base model | Repeated semantic errors in a well-labeled drone/camera command domain | A sufficiently varied, independently reviewed training set disjoint from every evaluation set; separate validation and new sealed test; adapter-conversion and runtime checks. [Hugging Face PEFT](https://huggingface.co/docs/peft/developer_guides/quantization) documents four-bit QLoRA, and [llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) documents LoRA adapters. These generic tools do **not** prove a Qwen3.5 adapter will train, convert, improve this task or fit the Pi. |
| A different or larger local model | Semantic capacity if the 4B model keeps failing unfamiliar language | Same task corpora and safety gate, then fresh sealed test, RAM/CPU/power/thermal measurements on the owned Pi. The [Pi 5 product brief](https://datasheets.raspberrypi.com/rpi5/raspberry-pi-5-product-brief.pdf) specifies a quad-core Cortex-A76 and memory options; model-card benchmark differences do not establish concurrent camera/ASR speed on this aircraft. |
| Readiness and workload scheduling | Cold timeout and load contention, not semantic correctness | Production-path cold and warm proposal times, Stop while a request is in flight, and ten-minute Pi camera/tracking/ASR coexistence. [llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) documents an empty-run warmup, but this project's first real structured request still took 22.229 s after server health. The app client currently allows eight seconds. |

The PC has an RTX 4050 laptop GPU with 6,141 MiB reported VRAM and 32 GB physical RAM (local `nvidia-smi` and Windows inventory, 27 September). A small QLoRA experiment may be worth feasibility testing later, but available VRAM alone does not prove this multimodal 4B architecture or training stack will fit. Do not upload private camera imagery, voice or biometric data for training. Command-text examples can be synthesized and owner-reviewed without personal data. Training is justified only if broad, fresh open-development cases show persistent *model* semantics after the guard fixes; compare the trained adapter against the unchanged base on the same new evaluation and accept only a fresh sealed pass.

The live plan remains offline-first. Optional online interpretation may be evaluated for coverage, but cannot be the sole way to operate essential missions under [the interaction contract](../phone-drone/interaction-contract.md). Any future model still produces reviewable diagnostic proposals, never direct aircraft authority.
